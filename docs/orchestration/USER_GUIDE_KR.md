# AI 작업 사용법

앱 안에서는 **설정 → AI 작업 → 사용법**과 **새 AI 작업** 대화상자 맨 아래에서 같은 기본 흐름을 볼 수 있다.
AI 작업은 개발 빌드의 미리보기 기능이다. 인증 연결 절차, 복구·재조정, 검증 격리, 자동 통합 같은 운영·내부 세부는 [상세 안내](USER_GUIDE_DETAILS_KR.md)에, 릴리스 판정과 남은 제약은 [구현 상태](IMPLEMENTATION_STATUS.md)에 있다.

## 빠르게 시작하기

1. **준비** — 사용할 CLI를 설치하고 공식 CLI에서 로그인한다(Codex는 `codex login`, Claude Code는 `claude` 실행 후 `/login`). **설정 → AI 작업 → 빠른 설정**에서 설치된 CLI 카드의 모델을 확인하고 **이 모델로 팀 만들기**를 누른다. 현재 네 역할이 모두 검증된 조합은 Apple Silicon macOS의 Codex 0.154.0 + ChatGPT 구독 + `gpt-5.6-luna`다.
2. **시작** — 터미널에서 작업할 저장소 폴더를 연 pane을 오른쪽 클릭해 **이 폴더에서 AI 작업…**을 고르거나 상단 막대의 **새 AI 작업**(`Cmd/Ctrl+Shift+M`)을 누른다. 목표를 적고 **만들고 시작**을 누른다. 커밋하지 않은 변경이 있으면 **커밋하지 않은 변경을 포함해서 시작**이 기본으로 켜져 있어 지금 보고 있는 작업 트리 그대로 시작한다. 앱이 대신 커밋하거나 stash 하지는 않는다. 체크를 끄면 현재 커밋(HEAD)이 기준이 되고, 그때는 변경을 정리한 뒤 시작한다.
3. **진행** — Lead가 할 일을 나누고 Builder가 각자 복사본(작업 공간)에서 일한다. 사람의 판단이 필요할 때만 **결정 필요**로 묻는다.
4. **확인** — 합친 결과를 저장소별 검증 명령과 독립 리뷰로 확인한다(빠른 모드는 리뷰 생략).
5. **확정** — 결과 화면에서 변경을 보고 **이 결과 확정**을 누른 뒤 **결과 가져오기**의 명령으로 내 브랜치에 반영한다.

OpenCode는 저장된 연결이 필요해 빠른 설정으로 만들 수 없다. [직접 설정하기](USER_GUIDE_DETAILS_KR.md#직접-설정하기)와 [OpenCode 인증 연결](USER_GUIDE_DETAILS_KR.md#opencode-인증-연결)을 따른다.

## AI 작업이 하는 일과 언제 쓰나

AI 작업은 목표 하나를 AI 팀에 맡긴다. **Lead**가 목표를 할 일로 나누고, **Builder**가 할 일마다 데몬이 만든 별도 Git 작업 공간에서 구현하며, 자동 통합 단계가 변경을 합친다. 합친 결과에 검증 명령을 돌리고 **Reviewer**가 독립 리뷰를 한 뒤, 사용자가 확정하면 끝난다. 충돌은 **Integrator**가 맡는다. 검증 실패나 중요한 리뷰 지적은 한도 안에서 수정 계획으로 이어진다.

| | 터미널에서 `claude`·`codex` 직접 쓰기 | AI 작업 |
| --- | --- | --- |
| 작업 위치 | 내 체크아웃에서 바로 파일을 바꾼다 | 데몬 소유의 복사본에서 일하고, 내 브랜치는 확정 뒤 직접 가져올 때만 바뀐다 |
| 진행 방식 | 대화하며 한 에이전트를 이끈다 | 목표·완료 조건을 주면 여러 할 일을 병렬로 진행하고, 필요할 때만 묻는다 |
| 확인 | 직접 테스트하고 읽는다 | 결과마다 검증 명령·독립 리뷰·확정 체크리스트를 거친다 |
| 끊김·재시작 | 세션을 다시 열어 이어 간다 | 실행 기록과 작업 공간을 보존하고, 결과를 모르는 실행은 격리한 뒤 새 시도를 고르게 한다 |
| 한도 | CLI 자체 설정 | 병렬 수·시도·활성 시간·비용 상한을 AI 작업마다 둔다 |

**AI 작업이 맞는 경우**: 완료 조건이 분명하고 여러 파일·여러 할 일로 나뉘는 작업, 검증 명령이 있는 저장소, 결과를 커밋 단위로 받아 검토하고 싶을 때.
**터미널이 맞는 경우**: 코드 탐색·짧은 질문·대화형 디버깅, 커밋하지 않은 변경 위에서 바로 이어서 고칠 때.

에이전트가 떠 있는 pane의 ⋯ 메뉴에는 **이 저장소에서 AI 팀에 맡기기…**가 있다. 같은 저장소로 새 AI 작업을 열지만 지금 대화는 옮겨지지 않으므로 목표를 새로 적는다.

## 진행 화면 읽는 법

AI 작업마다 탭이 하나 열린다. 왼쪽은 **Lead 대화**(사용자 목표, 채택된 계획, 진행 보고)와 아래의 **AI 작업 전체에 요청** 입력창이다. 오른쪽 위는 **할 일** 목록, 오른쪽 아래는 **실행 상세**와 **결과** 중 하나를 보여 준다. 좁은 화면에서는 **대화 / 할 일 / 결과**를 바꿔 가며 본다.

- **헤더**: 제목, 상태·단계, 활성 시간(사용/한도). **실행 제어 ▾**에 **새 실행 일시정지**, **계속 실행**, **AI 작업 중단**, **AI 작업 한도…**, **팀 바꾸기…**가 있다. 일시정지·중단이 끝나기를 기다리는 동안에는 종료 확인을 기다리는 실행 수와 **첫 실행 상세 열기**가 보인다.
- **결정 필요 배너**: `결정 필요 N: …`와 **열기**. 열면 결정 패널이 상황 한 줄, 판단 자료(제안된 할 일, 파일 변경, 충돌 파일, 영향받는 할 일), 선택지 버튼과 누르면 생기는 일, **자세히**를 보여 준다. 답하면 다음 결정으로 넘어가고 “답변을 저장했습니다”를 잠깐 알린다. 결정은 다른 탭에서 강제로 화면을 바꾸지 않는다.
- **확정 대기**: 단계가 확정 대기로 바뀌는 순간 오른쪽 아래가 한 번 결과 화면으로 전환된다(좁은 화면은 결과 탭). 그 뒤에는 사용자가 고른 화면을 유지한다. 결과 버튼 옆 점은 확정 대기를 뜻한다.
- **할 일 목록**: 행마다 상태 기호와 문구(선행 할 일 대기, 실행 대기, 시작 중, 실행 중, 응답 필요, 변경 확인 중, 진행 불가, 할 일 완료, 실행 실패, 취소됨, 계획에서 대체됨), 모델, 시도 횟수를 보인다. 아래 줄에는 대기 이유, 남은 재시도, 시도 이력, **실험적 연결** 배지가 붙는다. 3분 넘게 활동이 없으면 “상태 확인 중”으로 보이지만 실패 판정은 아니다. 카운터 `실행 N · 완료 N · 결정 N`, 필터 전체/실행 중/응답 필요/대기/완료, 제목·역할·모델 검색이 있다.
- **할 일 상세**: 역할·모델·시도·저장된 실행 시간, 상태 안내 한 줄(+ **자세히**), 제어 버튼(**이 할 일 실행 중단**, **다시 시도**, **모델 변경**)과 비활성 사유, **이 할 일에 추가 지시**. 탭은 활동(새 출력을 따라가며, 위로 올리면 멈추고 **최신으로**), 변경·검증(전체 결과 중 이 할 일 관련 항목을 먼저)이다.
- **탭 배지**: 우선순위대로 하나만 보인다 — `결정 필요 N` > `확정 대기` > `실패` > `실행 중 N` > `완료`. 보고 있지 않은 탭이 결정 필요로 바뀌면 짧게 알린다.
- **알림 센터**: 새 결정 필요, 확정 대기 진입, 실패를 한 줄씩 남긴다. 그 AI 작업 탭을 보고 있으면 남기지 않고, 창이 숨어 있을 때 결정 필요·확정 대기는 데스크톱 알림도 보낸다.
- **AI 작업 목록**: 상단 막대의 ☰ 버튼이나 메뉴에서 연다. 결정 필요 / 확정 대기 / 진행 중 / 끝남 / 보관됨으로 묶고, 제목·저장소로 검색하며, 행을 누르면 탭을 연다. 탭은 최대 16개까지 열린다.
- **탭 닫기와 보관**: 탭을 닫아도 AI 작업은 계속 실행되며 목록에서 다시 연다. **보관**은 끝난 AI 작업만 가능하고 파일과 작업 공간을 지우지 않는다. 보관 직후 뜨는 토스트의 **되돌리기**로 되살리거나, 목록의 보관됨에서 **보관 해제**한다.
- **연결 끊김**: `연결 끊김 · 실행 상태 미확인`이 보이면 화면이 흐려지고 변경 버튼이 잠긴다. 데몬의 실행은 계속되며, 다시 연결되면 자동으로 동기화한다. 일시 지연은 `동기화 지연`과 **다시 시도**로 따로 보인다.

## 결과 확정과 가져오기

결과 화면 위쪽에는 상태, **확정하려면** 체크리스트, **이 결과 확정** 버튼(막혀 있으면 첫 이유), **수정 요청**, **이 결과 버리기**, 결과 가져오기 요약이 있다. 아래쪽에는 직접 확인할 항목, 요구사항 충족표, 변경 파일, 검증과 로그, 리뷰 지적, 남은 한계, 결과 가져오기, 실행 이력/사용량이 있다.

- 체크리스트 항목(해당하는 것만): 확정 대기 단계, 필수 할 일 완료, 요구사항 검증 통과, 검증 입력 쓰기 차단 보장, 독립 리뷰 완료, 차단·주요 지적 없음, 직접 확인 완료, 진행 중이거나 결과가 불명확한 실행 없음, 답하지 않은 차단 결정 없음. 항목 옆 링크로 해당 할 일·검증·지적·결정으로 이동한다.
- **직접 확인할 항목**: 사용자 확인 조건, 입력 쓰기 차단이 보장되지 않은 검증, 결과를 알 수 없었던 과거 실행을 직접 확인하고 체크한다. 화면을 연 뒤 결과가 바뀌면 확정 버튼이 막히고 체크가 풀리므로 **갱신**한 뒤 다시 확인한다.
- **확정**은 되돌릴 수 없다. 검증과 직접 확인을 기록하고 이 결과를 최종으로 확정하지만 원래 브랜치에는 자동으로 반영하지 않는다.
- **결과 가져오기**: 결과는 저장소의 비공개 참조에 커밋으로 보관된다. 화면이 현재 브랜치를 확인해 추천 명령을 고르며, 명령을 복사하거나 **터미널에서 열기**(저장소 경로로 새 터미널 탭을 열고 명령을 복사, 자동 실행하지 않음)를 쓴다.
  - 현재 브랜치에 병합: `git merge --ff-only <결과 커밋>` — 현재 브랜치가 AI 작업의 시작 커밋에 있을 때만 성공한다.
  - 새 브랜치로 가져오기: `git switch -c ai/<제목에서 만든 이름> <결과 커밋>` — 브랜치가 그새 움직였으면 이 방법을 추천한다.
  - 변경 보기: `git diff <시작 커밋> <결과 커밋>`.
- **후속 작업**: 완료된 AI 작업의 대화 입력창 자리에 **이 결과로 후속 AI 작업 만들기**가 나온다. 이전 AI 작업이 확정됐고 같은 저장소면 새 AI 작업은 이전 확정 결과 커밋 위에서 시작한다(대화상자에 `이전 확정 결과 위에서 시작 · 커밋 …` 표시). 확정되지 않았거나 다른 저장소면 현재 HEAD에서 시작한다. 실패하거나 중단된 AI 작업은 **같은 목표로 새 AI 작업**을 권한다.
- **수정 요청**은 Lead 대화 입력창으로 이동한다. **이 결과 버리기**는 AI 작업을 중단하고 종료가 확인되면 보관한다(파일·작업 공간은 지우지 않는다).

## 빠른 모드(리뷰 생략)

새 AI 작업 대화상자의 **리뷰**에서 **리뷰 생략(빠름)**을 고르면 Reviewer 없이 검증 명령과 직접 확인만으로 확정한다. 팀에 Reviewer가 없으면 이것이 기본값이고, **리뷰 포함(권장)**을 고르면 Reviewer 연결이 필요하다. 체크리스트에서 독립 리뷰 항목이 빠지므로 변경은 직접 더 꼼꼼히 확인한다. 검증 명령이 없거나 이 OS에서 실행할 수 없으면 확정 근거는 사용자 확인뿐이다.

## 실험적 연결

연결마다 신뢰 표시가 하나 붙는다: **출시 검증됨** / **이 PC에서 확인됨** / **실험적** / **미확인**. 빠른 설정 카드에서 이 CLI 버전이 **자동 실행 미검증**이거나 **같은 계열 버전은 검증됨 · 지금 확인으로 확정**이면, 필요한 기능이 구현된 경우에 한해 **실험적으로 사용**에 동의하고 팀을 만들 수 있다(**이 PC에서 확인됨**이면 동의 없이 바로 쓸 수 있다). 결과 형식·취소·파일 변경 범위가 예상과 다를 수 있다.

- 동의는 연결 하나당 한 번이다. CLI가 업데이트돼도 다시 동의할 필요가 없고, 설정에서 **지금 확인**만 누르면 된다.
- 일부 조합은 빠른 모드(리뷰 생략)에서만 쓸 수 있다.
- 표시가 남는다: 새 AI 작업 대화상자의 “실험적 연결 포함”, 필요한 기능이 동의로 열린 할 일 행과 상세의 **실험적 연결** 배지, 결과 화면의 경고와 체크리스트 정보 행. 정보 행은 확정을 막지 않는다.

## 작업 공간 정리

할 일마다 만든 복사본 폴더(작업 공간)는 AI 작업이 끝나도 자동으로 지우지 않는다. 사용자가 누를 때만 정리한다.

- **AI 작업 목록** 머리에 전체 사용량(`AI 작업 공간 1.2 GB`)이 보이고, 끝남·보관됨 행에 **작업 공간 정리 (크기)** 버튼 또는 정리할 수 없는 이유가 붙는다.
- 확정 직후 결과 화면에 **작업 공간 (크기) 정리** 제안이 나온다. 보관 토스트에는 목록에서 정리할 수 있다는 안내와 **목록 열기**가 붙는다.
- 확인창: 이 AI 작업의 복사본 폴더와 임시 기록을 지운다. 확정된 결과 커밋은 남아 계속 가져올 수 있고, 원래 저장소는 건드리지 않는다.
- 정리 뒤에는 지운 수·확보한 용량과 남긴 항목의 이유(커밋되지 않은 변경, 실행이 사용 중, 확인할 수 없는 폴더, 시간이 걸려 건너뜀 등)를 보여 준다. 건너뛴 항목은 다시 정리하면 이어서 지운다.
- 진행 중인 AI 작업이나 종료가 확인되지 않은 실행이 있으면 정리할 수 없다. 멈춘 실행은 할 일 상세의 **프로세스 종료를 직접 확인했습니다**로 정리할 수 있다.

## Claude Code 터미널 → Z.ai(GLM)

이 절은 Iyagi이 여는 대화형 Claude Code **터미널**에 관한 것이며 AI 작업 실행과는 별개다. AI 작업은 [상세 안내](USER_GUIDE_DETAILS_KR.md#claude-인증-연결)에서 설명한 데몬 연결 저장소(`iyagi-termd connection add`)를 계속 사용한다. 두 저장소는 키를 공유하지 않으므로 둘 다 쓰려면 양쪽에 각각 등록한다.

1. **설정 → 연동 → Z.ai Coding Plan**에서 키를 한 번 저장한다. 키는 이 기기의 앱 전용 저장소(`<데이터 디렉터리>/secrets/zai.enc`)에 암호화해 보관하며 키체인 암호를 묻지 않는다. 데몬은 실행 시점에 같은 파일을 읽는다. 키를 저장하면(연결된 데몬이 라우팅을 지원할 때) **Claude Code 실행을 Z.ai(GLM)로 라우팅** 스위치가 켜지고, 키를 삭제하면 꺼진다. 스위치를 끄는 것은 구 데몬에서도 항상 가능하다.
2. 주 모델을 고른다: **GLM-5.3**(`glm-5.3[1m]`, 기본값) 또는 **GLM-5.3-Flash**(`glm-5.3-flash[1m]`). haiku/백그라운드 슬롯은 항상 GLM-5.3-Flash다. 키가 없거나 실행 중인 데몬이 라우팅을 지원하지 않으면 두 컨트롤은 안내 문구와 함께 비활성화되고, 그 상태에서 라우팅이 필요한 실행은 Anthropic 직결로 조용히 대체하지 않고 메시지와 함께 거절한다.

라우팅 대상: 빈 프로젝트 화면의 Claude quickstart, CLI 종류가 Claude Code인 관리 실행 프로필, Claude 세션의 **재개**. 일반 셸은 라우팅하지 않는다. 셸에서 직접 `claude`를 입력하면 그 pane은 사용자 셸 환경의 설정을 그대로 따른다.

데몬이 키를 직접 해석해 다음 환경을 주입한다. 키는 실행 요청·DB·pane 제목·로그에 들어가지 않는다.

| 변수 | 값 |
| --- | --- |
| `ANTHROPIC_BASE_URL` | `https://api.z.ai/api/anthropic` |
| `ANTHROPIC_AUTH_TOKEN` | 저장한 Z.ai 키 |
| `ANTHROPIC_DEFAULT_OPUS_MODEL`, `ANTHROPIC_DEFAULT_SONNET_MODEL` | 선택한 주 모델 |
| `ANTHROPIC_DEFAULT_HAIKU_MODEL` | `glm-5.3-flash[1m]` |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW` | `1000000` |
| `API_TIMEOUT_MS` | `3000000` |
| `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` | `1` |
| `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST` | `1` |

상속된 `ANTHROPIC_API_KEY`, `CLAUDE_CODE_OAUTH_TOKEN`, `CLAUDE_CODE_USE_BEDROCK`/`VERTEX`/`FOUNDRY`/`GATEWAY`, `ANTHROPIC_MODEL`, `ANTHROPIC_DEFAULT_MODEL`, `ANTHROPIC_SMALL_FAST_MODEL`, `CLAUDE_CODE_SUBAGENT_MODEL`은 위 값을 적용하기 전에 자식 환경에서 제거하므로 셸 프로필이 가리키는 다른 게이트웨이가 새어 들어오지 않는다. `CLAUDE_CONFIG_DIR`·`HOME`·임시 디렉터리는 건드리지 않는다. 사용자의 `~/.claude`(hooks·상태 표시줄·plugins·MCP 서버·세션·재개)가 그대로 동작하고 `--model` 인자도 붙이지 않으므로 `/model`과 `settings.json`도 계속 쓸 수 있다. 실행 프로필이 인증·base URL 변수를 이미 지정하고 있으면 덮어쓰지 않고 환경 충돌 메시지와 함께 실행을 거절한다.

저장된 claude.ai 로그인은 라우팅 중에도 로그인 상태로 남지만 사용되지 않는다. Claude Code가 토큰 환경 변수가 로그인보다 우선한다는 한 줄 경고를 출력할 수 있으며 이는 정상이다. 라우팅 중에는 Anthropic 서버가 필요한 기능을 쓸 수 없다: Remote Control, `/schedule`, claude.ai MCP 커넥터, MCP 도구 검색, 자동 업데이트.

Windows: Claude Code를 네이티브 설치 프로그램으로 설치하고 그 `claude.exe`를 프로필 실행 파일로 등록한다. npm의 `claude.cmd` shim은 관리 실행 프로그램이 될 수 없고(02 §3) quickstart도 shim은 건너뛴다.

실행 오류와 대처: `zai_key_missing` — 설정 → Z.ai Coding Plan에서 키를 등록한다. `daemon_outdated` — 실행 중인 데몬이 라우팅을 지원하지 않으므로 데몬을 업데이트하거나 다시 시작한다. `claude_provider_program_mismatch` — 프로필의 실행 파일이 Claude Code가 아니다. `claude_provider_env_conflict` — 프로필에서 충돌하는 환경 변수를 제거한다. [Z.ai Claude Code 연결 안내](https://docs.z.ai/devpack/tool/claude), [Claude Code 환경 변수](https://code.claude.com/docs/en/env-vars), [LLM gateway 설정](https://code.claude.com/docs/en/llm-gateway-connect)

### ccd / ccg 셸 명령

pane 없이 터미널에서 바로 Claude Code를 시작하는 셸 함수 두 개다. `ccd`는 Anthropic(사용자의 claude.ai 로그인)으로, `ccg`는 위에서 등록한 키로 Z.ai(GLM)로 라우팅해 시작한다. 둘 다 이 절에서 현재 고른 주 모델을 그대로 따른다.

**설정 → 실행 프로필 → 셸 명령 ccd / ccg**에서 설치한다. 설치하면 `~/.zshrc`에 3줄짜리 마커 블록과 앱 전용 스크립트가 함께 쓰이며, `source ~/.zshrc`를 실행하거나 새 터미널을 열어야 반영된다. 셸 시작 파일 어디에든 사용자가 직접 만든 `ccd`나 `ccg` alias·함수가 이미 있으면 덮어쓰지 않고 설치를 거부한다.

`ccd`는 `~/.claude/settings.json`에 이미 있는 Z.ai `env` 블록을 덮어쓰지 못한다 — Z.ai 자체 설치 스크립트를 이전에 실행했다면 그 블록을 직접 지워야 `ccd`가 Anthropic이 아닌 Z.ai로 계속 연결되는 일을 막을 수 있다. 저장한 Z.ai 키를 삭제하면 `ccg`는 시작하는 대신 키를 등록하라는 안내 메시지를 출력한다.

zsh 전용(macOS/Linux)이며 Windows는 지원하지 않는다.
